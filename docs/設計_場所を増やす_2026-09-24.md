# 設計：場所を増やす（区画・部屋・デバイス）2026-09-24

書いたのは研究トークE（マック）。本人の指示：
「①場所を育てる部分を作りたい（いまはシンクだけ・キャラとの関係が一定に感じる）
②これを型として、画角を広げ、デバイスを足し、別の部屋にも増やせる設計にしたい」

**10/4 に凍結。それまでに作るのは1部屋ぶん。ただしデータの形は最初から多部屋に耐える形にする。**

---

## 1. いま何が「一定」なのか（コードを読んだ事実）

| | 現状 | 出どころ |
|---|---|---|
| 見る範囲 | **シンクの切り出し1か所だけ**。機嫌（M値）もそこから作る | `spirit.py` `ZONE_NAMES = ("シンク",)` |
| 関係 | なつき度0〜10・5段階。1滞在で+1・1日3回まで | `BOND_MAX` / `BOND_DAILY_MAX` |
| 関係の出方 | 段階で変わるのは**話し方の指示文だけ**。表情も姿も全員同じ | `BOND_STAGES` |
| 積もり | **どこにも残らない**。誰がどの場所を整えたかの履歴が地霊の側に無い | faces に `cares`（合計だけ） |

→ 「キャラとの関係が一定」は体感ではなく実装のとおり。
**関係は立ち上がるが、積もらない。**（位置づけの作業で、トーキング・アイに同じ穴を見つけた）

## 2. すでにある土台（作り直さなくてよいもの）

- **区画ごとの前後比較**：`_compare_zone(before, after, name)`・`ZONE_FIXTURES`（区画ごとの説明文）
- **カメラを向ける仕組み**：`/spirit/checkpose` に向きを立てる → 橋渡しが `go_check` で首を振り、
  `take_good_shot` が「ぶれていない・画角が合っている・動きがない」1枚が撮れるまで撮り直す
- **アプリ側のゾーン**：`zones` コレクション、`/zone/{id}` のタイムライン（NFCタグの行き先）
- **区画は立て直せる**：画角が変われば `st["zones"] = []` で作り直す作りになっている

**足りないのは「区画が1つしか登録されていない」ことと、「人×区画の履歴が無い」ことだけ。**

## 3. 形（これを型にする）

```
場所（space）      = 部屋ひとつ。キッチン／ゼミ室／畑
  └ 区画（zone）   = その部屋の中で「見る単位」＝人が世話する単位
  └ 機械（device） = カメラ・C3・スピーカー・橋渡し
  └ 地霊（spirit） = 場所に1体。顔は全員に同じ（#6 の景観）
人 × 区画の履歴     = 誰が、どの区画を、何回整えたか（#6 の風景）
```

**大事な一致**：地霊が見る区画と、アプリで人が投稿するゾーン（`/zone/{id}`・NFCタグ）を
**同じ zone にする**。別々に持つと、増やすたびに二重に設定が要る。

### 置き場所（Firestore）

```
spaces/{space_id}                 name, tz, persona, created_at
spaces/{space_id}/zones/{zone_id} name, pose(x,y), crop, fixture, order, active,
                                  ref, band, min_conf, anchor   ← 向きの守り（9/24 B の指摘）
spaces/{space_id}/devices/{dev}   kind(camera|c3|voice|bridge), last_at, note
faces/{pid}                       … + cares_by_zone:{zone_id: n, …}, last_zone, last_zone_at
```

- **`pose`＝その区画を見るためのカメラの向き**。いまの「シンク」は既存の向きをそのまま1件目に入れる
- **`crop`＝写真のどこを切り出して判定するか**（いまシンクで使っている割合指定を、区画ごとに持つ）
- **`fixture`＝その区画の説明文**（`ZONE_FIXTURES` の中身を、コードから設定へ出す）
- **`active`**＝見回りに入れるかどうか。増やすときは足すだけ、止めるときは false
- **向きの守りを区画ごとに持つ（9/24・B の指摘）**。いまの守りは4か所ともシンク専用で、
  このまま区画を増やすと**シンク以外は「違う景色」として全部飛ばされ、判定が一切出ない**：
  - `ref`＝その区画の見本の写真（いまは `AIM_REF_OBJ` が1枚だけ）
  - `band`＝画面のどの帯で測るか（いまは `VIEW_BAND=(0.5,1.0)` ＝下半分。シンクだから成立している。
    棚や机では「動かない所」が別の位置にある）
  - `min_conf`＝同じ景色と認める線（いまは 0.08。**シンクの見え方で測った数字**。
    模様の少ない壁では、正しい向きでも下回りうる）
  - `anchor`＝錨。**いまは1枚しか持てず、区画を順に回すと互いに上書きし合う**。
    さらに B の訂正（9/24）：錨はクラウドが同時に何台も動くため**台ごとの頭の中にあり、実際には効いていない**。
    区画ごとに持たせるなら **状態（Firestore）に保存する**形にする
  - **橋渡し側（`bridge/shot_check.py`）も同じ形にそろえる**
- **新しい区画を足す手順には「線を測る」が必ず入る**（B）：その向きで見本を撮り、
  同じ向きの2枚で確かさを実測して `min_conf` を決める。**測らずに 0.08 を使い回すと、静かに全部飛ばされる。1区画あたり半日。**

**コードに区画名を書かない。**これが「量産できる設計」の核心。
別の部屋を足すときにやるのは、①`spaces` に1件足す ②区画をいくつか登録する
③機械をその部屋に割り当てる——**コードは触らない**。

## 4. 「積もる」をどう出すか（#15・#17・#22 を壊さない範囲で）

**やらないこと**：点数を見せる／順位をつける／「片づけて」と促す／名指しで掲示する。
**やること**：その人が手をかけてきた区画を、地霊が**覚えていて、佇まいに出す**。

1. **向く**：その人が来たとき、地霊はその人がよく整えてきた区画のほうを見る（向きが変わるだけ）
2. **混じる**：挨拶の一言に、その区画の具体が混じる（「このあいだ、ここ、きれいになってた」）。
   **要求はしない。返事も待たない**（#22）
3. **区画ごとの機嫌**：機嫌は区画の状態の合成にする。荒れている区画があれば、そちらを気にしている
   ——**状態として**。催促にはしない（#15）

> **判定基準（位置づけの作業で引いた線）**：応じなかったとき何も残らない／タイミングは人が決める／
> 何をするかも人が決める。**1つでも破ったら、ただの通知装置に落ちる。**

## 6. 増やすときに効いてくる制約（先に書いておく）

- **首を振るほど景色が揺れる**。橋渡しのコメントに実測がある——90秒ごとに探していた頃は
  1日79回振り、そのたび前後比較が壊れた。**区画を増やす＝首振りが増える**ので、
  見回りの間隔（`SWEEP_COOLDOWN` 600秒）と、区画ごとの「前と比べる」の成立条件を必ず見直す
- **AI の呼び出しが区画数だけ増える**。いまの上限は1日400回（`JUDGE_DAILY_CAP`）。
  4区画なら単純に4倍。**見回りは全区画を毎回見ない**（順番に1つずつ）
- **凍結後は設定を変えない**。区画を足すのも設定変更なので、**10/4 までに確定**する
- **別の部屋を足すのは凍結後**（10月以降）。いま作るのは入れ物だけ。
  観察期間中に2部屋目を足すと、比べる相手が変わる

## 7. 量産するときの手順（凍結後・この設計の結果）

1. 部屋を1つ `spaces` に足す
2. カメラを置き、**区画ごとに向きを覚えさせる**（画面から向きを決めて保存。いまの `/spirit/home` と同じやり方）
3. C3・スピーカーをその部屋に割り当てる
4. 区画のNFCタグを貼る（行き先は `/zone/{zone_id}`。アプリ側と同じ zone なので、そのまま使える）

**コードは触らない。**触るのは設定だけ。
