## 5. 作業コピー（9/19 01:3x 決定：作業トークは1トーク1コピー）

9/17 に研究トークBが研究トークCの未コミットの変更を push しかけた根は、**4つのトークが同じ作業フォルダで動いていた**こと。
これからは **作業トークは自分の作業コピー（git worktree）を持ち、共通フォルダには進行役しか居ない**。

```
arigato/                        ← 進行役だけ（枝 main）。docs・札・logs はここが正
arigato/.claude/worktrees/B/    ← 研究トークB（枝は EnterWorktree が作る）
arigato/.claude/worktrees/C/    ← 研究トークC（同上）
マック                          ← 自分のクローン。push は 9/22 の判断まで無し
```

### 入り方（各トークが自分でやる。1回だけ）
1. 共通フォルダに**自分の未コミットの変更があれば**、自分のファイルだけ退避：`git stash push -u -m "<自分の名前>" -- <自分のファイル…>`
2. `EnterWorktree`（name は自分の役割名：`B`・`C`）。origin/main から新しい枝で作業コピーができ、トークの居場所がそこに移る
3. 退避したものを戻す：`git stash pop`（stash はコピー間で共通）
4. 札の自分の行に「作業コピー：`.claude/worktrees/◯`」と書く

### 作業コピーに移ったあとの決まり
- **札と作業ログは絶対パスで触る**（作業コピーの中の `docs/` は自分の枝の写しで、他のトークからは見えない）
  - 札：`C:\Users\kengk\research-os\work\arigato\docs\いま触っているもの.md`
  - ログ：`C:\Users\kengk\research-os\secretary\logs\YYYY-MM-DD.md`
  - `docs/9月のタスク.md` は進行役の持ち場。**書き換えず、進行役にメッセージで「これが終わった」と送る**
- 自分の枝には自由に commit する（他人の変更は混ざらないので `git add -p` は要らなくなる）
- ラズパイへ置くときは、**自分の作業コピーのファイル**を置く（他人の未コミットの塊が混ざらない）

### 本番へ入れる（push）とき
1. 札の鍵「push」を取る
2. `git fetch origin && git rebase origin/main`（他のトークの分を下に敷く）→ 手元で動くことを確かめる
3. `git push origin HEAD:main`（`server/` `pwa/` を含めば配信が走る。`deploy.yml` が入れ替え後に主な口を自動で確かめる）
4. 鍵を放し、**進行役に「push した」と送る**（進行役が共通フォルダで `git pull --ff-only` する）

### 進行役の決まり
- docs を commit する前に `git pull --ff-only`（作業トークの push で main が進んでいる）
- 共通フォルダに残っている**持ち主のいない古い未コミット**（`esp32cam/`・`voice/manner.py`・`TODO.md`・`docs/設置手順_2026-08-29.md`。7〜8月のもの）は、当面そのまま。持ち主が分かったらそのトークに引き取らせる
