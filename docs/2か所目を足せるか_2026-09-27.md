# 2か所目を足せるか（2026-09-27・本人の問いへの見立て）

> 「これを型にして、他の場所にも設置できるようになっている？」
> 「誰でも、どこにでも、新たな場所を追加できるマニュアルが欲しい」

**結論：いまは足せない。**足りないのは道具ではなく、**「場所」という考え方そのもの**である。
いまの装置は**「場所は1つしかない」という前提**で全体が組まれている。

**ただし、いちばん手間のかかる部分（区画の設定・判定の決まり）は、すでに横展開の形になっている。**
下の「そのまま使える」を見てほしい。**作り直しが要るのは入れ物のほうで、中身ではない。**

## 1. そのまま使える（場所に縛られていない）

| もの | なぜ使えるか |
|---|---|
| **区画の設定**（`ZONE_CFG_DEFAULT`） | 向き・帯・線・切り出し・問い・決まり・`decided` が1か所にまとまっている。**新しい場所の区画も、この形で書ける** |
| **判定の決まり**（`change`／`dwell`） | 「前と今を見比べて変わった向きだけを見る」は場所によらない |
| **橋渡し**（`bridge/tapo_bridge.py`） | 宛先・カメラ・鍵が環境変数（`SPIRIT_SERVER`・`TAPO_URL`・`SPIRIT_KEY`）。**2台目の PC で、そのまま動く** |
| **問いの文面**（`ask`） | 区画ごとに書く形になっている |
| **今日測った数字**（映像の遅れ11秒・1周130秒・線と帯の決め方） | **測り方が残っている**ので、新しい場所でも同じ手順で測れる |

## 2. 直せば置ける（場所の札を足すだけ）

**いま全部が1つの場所に紐づいている所。**「どの場所か」を足せば動く。

| もの | いまの形 | 直し |
|---|---|---|
| 状態 | Firestore の **`spirit/state` 1件**。なつき度・在室・区画・基準写真の時刻・機嫌が全部ここ | `spirit/state_<場所>` に分ける |
| 写真 | `spirit/latest.jpg`・`spirit/zoneref/<id>.jpg`・`spirit/zonecheck/base_<向き>.jpg` の**決め打ち** | 名前に場所を入れる |
| 口（API） | **68個すべて**が「その1つの場所」を指す。`_load()` を呼ぶ所が **43か所** | `?place=` を受け取り、`_load(place)` にする |
| インスタンスの覚え | `_state_cache`・`_last_good`・`_ALIVE`・`_ai_ok`・`_log_ok` など**10個が、場所の区別なく1つ** | 場所ごとの辞書にする |
| 記録 | `spirit_log` に場所の欄が無い | `place` を足す（**過去の記録には無い**ので、欄が生まれた時刻を控える） |

**手間の見積もり：2〜3日。**単純だが**触る所が多い**（43＋68か所）。
**危ないのは、途中まで直した状態**である。場所の札を半分だけ付けると、
**2つの場所の数字が静かに混ざる。**混ざったことは記録に出ない。
**やるなら一度に全部やる。**

## 3. 作り直しが要る（決め直しが先。手を動かす前に人が決める）

| もの | 何が決まっていないか |
|---|---|
| **顔** | `faces` は場所の区別が無い。**いまの作りでは、2か所目に来た同じ人は「同じ p01」になる。**これでよいのか（場所ごとに別人として数えるのか）は**研究の問い**であって、実装の問題ではない（A の持ち場） |
| **地霊そのもの** | 機嫌・なつき度・性格・思い出が状態に1つだけ。**「場所ごとに別の地霊」なのか「1人が複数の場所を見る」のか。**設計の根（#6「人ごとの地霊」）に関わる |
| **C3（顔の画面）** | 1台につき1か所。**どの場所の地霊を映すか**を持っていない |
| **区画の名前** | 「シンク」は2か所目にもある。**名前が衝突する**（いまは名前が鍵） |
| **鍵** | `SPIRIT_KEY`・`NOTE_KEY`・`ANTHROPIC_API_KEY` は1組。**場所ごとに分けるか、共有か**（今日の残高切れを考えると、**装置用の鍵は分けたほうがよい**） |

## いちばん大きな壁

> **「場所」という入れ物が無いこと。**いまは「装置＝場所」で、状態も写真も記録も口も、**全部が名前の無い1つの場所**に紐づいている。

道具が足りないのではない。**2つ目を置いた瞬間に、2つの場所の数字が静かに混ざる。**
そして今日いちど身をもって分かったとおり、**静かに混ざるものは、記録を見ても気づけない。**

## マニュアルについて（本人の希望に直接答える）

**「新しい場所を足す手順書」は、いまでも書ける。ただし書けるのは下の2段目までである。**

1. **機械を置く**（カメラ・PC・C3）… 書ける
2. **区画を決めて測る**（向きを選ぶ → 見本を撮る → 帯と線を測る → 切り出しを決める → `decided` に残す）… **書ける。今日その手順を全部踏んだ**
3. **その場所を装置に登録する**… **いま「登録する」という考え方が無い**

**2 の手順書は、いま書く価値がある。**（今日の作業が、そのまま手順になる）
**3 は 10/4 の凍結より後の仕事。**いま作り直す話ではない。

## 補足：今日の作業が、そのまま2台目の手順になる

- 向きは**本人が写真を見て選ぶ**（機械には決められない。9/27「コンロが映ってないね」）
- 見本は**見回りが実際に撮る道順で撮る**（別の撮り方で撮ると、**永久に合わない**）
- 線と帯は**その場所で測る**（他所の値を流用しない。9/24 の 0.30 が 9/27 まで残っていた）
- **映像の遅れを測る**（カメラが「止まった」と言っても、映像は9〜10秒遅れる）
