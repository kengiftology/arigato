## 3. 1件の形（これを守る。埋まらない欄は「不明」と書く）

| 欄 | 中身 |
|---|---|
| 名前 | 事例の呼び名 |
| 出典 | **URL または書誌。出典の無いものは載せない** |
| 年 | 発表・公開の年 |
| 分野 | 共有空間の維持／感謝の流通／場所に人格／その他 |
| 1行要約 | 何をする装置・仕組みか（初見の人が読める言葉で） |
| 軸ごとの採点 | 0／0.5／1（軸は 5.2 で決まる） |
| 近さ | 本研究とどこが同じで、どこが違うか（各1行） |
| 確かさ | 読んだのは 本文／要旨／紹介記事 のどれか |

## 4. 触ってよいもの・いけないもの

- **触ってよい**：`thesis/`（事例・主張台帳・反論帳・references）、Notion の事例DB／タスクDB／盤面ページ
- **触ってはいけない**：カメラ・ラズパイ・C3・`server/`・`bridge/`・`pwa/`。**実機に関わるものは一切**
- **push は進行役の「どうぞ」を待つ。**`git add -p` で自分の分だけ選ぶ（作業フォルダは全トーク共通）
- 本人に何か頼んだら、**進行役に1行**（頼んだ／済んだ／取り下げた）

## 5. やってはいけないこと（研究の信用に直に効く）

1. **出典の無い事例を足さない。**思い出しや推測で書かない
2. **読んでいないものを「読んだ」ことにしない。**確かさの欄に正直に書く（要旨だけなら要旨と書く）
3. **採点を、こちらに都合よく動かさない。**先行が「○」なら○と書く。**都合の悪い事例ほど、位置づけの章では価値がある**
4. **本文の代筆をしない。**骨（見出しと各段落の要点）までにする

## 6. 判断の軸（すでに確定しているもの・2.5 節）

**催促を1つでも入れた瞬間、Nukabot と同じ列に落ちる。**分かれ目は「催促するか」の一点。
採点の軸には必ずこの3つを入れる：

| 問い | 不足の表示（よい） | 催促（だめ） |
|---|---|---|
| ① 応じなかったとき何が残るか | 何も残らない | 未達が残る |
| ② タイミングを決めるのは誰か | 人 | 装置 |
| ③ 何をするかを決めるのは誰か | 人 | 装置 |

**自分から書く弱点**（位置づけの章に必ず書く）：
**最初の一歩の説明は半分しかできていない。**散らかりは装置が無くても見えている。それでも動かなかった人が、
表情が付くと動く ── **その差を支える先行は30件の中に無い**。弱すぎれば誰も動かず、強めれば催促に落ちる。
**この刃の上にいることを、隠さずに書く。**
