# 週1の点検（4.4.1・2026-09-27 作成）

観察期（10/5〜12/6）は9週間ある。**人が毎日見に行かない前提**なので、
**週に1回、この1枚を上から順に叩く。**所要 10分。

**この点検で見つけたいのは「止まっていること」ではなく、「止まっているのに気づけないこと」である。**
9/27 の一日で、**気づけない形の停止が3つ**出た（AI の残高切れ・区画の判定が全部飛ばされていた・
見張りを作る直しが見張りの見ない形で装置を止めた）。**どれも記録は出続けていた。**

## 0. 押したあと（毎回・点検ではないが、ここに書いておく）

- **押したら、版が変わったことを `version` で確かめる。**「押した＝入った」ではない
  （9/26・9/27 に入れ替えが何度も打ち切られ、押した順に入らなかった）
- **押したあと、実物を1回流す。**テストが通ったことは、動くことの証明ではない
  （9/27 16:22、テストは「窓口を通しているか」を見ていて「窓口が動くか」を見ていなかった。
  一括置換が窓口自身を書き換え、AI の呼び出しが4分間すべて落ちた）

## 1. 生きているか（1分）

```bash
curl -s https://arigato-3ipecjbnha-an.a.run.app/spirit/health | python -m json.tool
```

| 見るところ | 良い状態 | 悪ければ |
|---|---|---|
| `stopped` | `[]` | 中身が止まっている機械の名前 |
| `ai_ok_ago` | 数千秒以内（人が来ていれば数分） | **30分を超えると `strict=1` が 503。残高切れを疑う** |
| `log_ok_ago` | 数分以内 | **記録が書けていない。数字が静かに減る** |
| `version` | 直前に押した版 | 入れ替えが失敗しているか、順番待ち |
| `deployed` | 直近の日時 | 同上 |

**`ai_ok_ago` と `log_ok_ago` は、その返事を書いた1台の話**である。クラウドは何台も動いているので、
**続けて2〜3回叩く。**本当に止まっていれば、どの台でも出る。

## 2. 区画の判定が通っているか（2分）

```bash
python scripts/zone_check.py 24      # 直近24時間
```

- **区画ごとに「比べられた」が1件以上あるか。**0件の区画があれば、そこは**死んでいる**
  （9/27 午前、シンク以外の4区画が**1件も通っていなかった**のに、記録は毎回出ていた）
- **飛ばした理由**が `view_mismatch` に偏っていれば、**見本と実際の画角がずれている**
- **1周の時間**（`round_sec`）が 150秒前後か。伸びていれば、待ち時間か区画の数を見直す
- **打ち切りの割合**。高ければ「人が去ったら残りから再開」が効いているかを見る
- **`prev_age`（前の写真の古さ）が 10800秒を超えていないか。**超えると比較が成立しない

## 3. 記録の数字（2分）

```bash
python scripts/passing_by.py 7       # 立ち寄り／通り過ぎ／測れていない
```

- **「測れていない」の件数を必ず見る。**率だけ見ない（9/27：測れていないが 60件中20件＝33%）
- 3つの合計が、その週の滞在の数と大きく食い違っていないか
