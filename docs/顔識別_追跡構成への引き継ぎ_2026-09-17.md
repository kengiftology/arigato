## 1. なぜ作り直すのか

## 3. 専門家の提案（カメラは今の1台・今の画角のまま）

**前提（本人に確認済み）**
- カメラはほぼ目線の高さ。天井から吊っていない（コードのコメントの「天井から」「真上」は誤り）。
- **入口（ドア）は画角に入っていて、入ってくる人は基本カメラのほうを向いて歩いてくる。**
  → 入室の数秒が、IDを決める主な場面になる。

**考え方**
- 正面が取れる瞬間は「入ってきた数秒」「誰かと話す」「ふと顔を上げる」で、それぞれ0.5〜2秒。1.5秒おきでは素通りしている。
- 「短い正面の瞬間を取りこぼさない（高いフレームレート）」＋「一度決めたIDを滞在の間ずっと引き継ぐ（追跡）」。正面が一度も出ない滞在は保留にして、中立に反応する。

**処理（ローカルで動かす）**
1. RTSP を 10〜15fps で受け、検出と追跡は 5〜10fps。
2. 人物検出：ultralytics の YOLO（yolo11n）、追跡：ByteTrack（`model.track()`）。
3. 顔：insightface の SCRFD。**人物の枠の中にある顔だけ採用**（鍋の誤検出が自然に落ちる）。
4. 顔の数値化：SCRFD の5点で 112×112 に揃え、**buffalo_l（w600k_r50）**。今の w600k_mbf は傾き・低画質に弱い。
5. 姿勢：自前の「起き具合」ではなく、buffalo_l の landmark_3d_68 の pitch / yaw / roll を使う。
6. 品質：顔幅・|yaw|・|pitch|・ボケ（ラプラシアン分散）・検出信頼度を合成した点数で十分。
7. トラックの顔：トラック内の品質上位10枚程度を、品質で重み付けして平均→正規化。
8. **追跡が途切れたときは服の見た目でつなぐ**（OSNet の小さい ReID か、上半身の色ヒストグラム）。確定したトラックの服は「この滞在の間だけ この服＝p02」として持ち、うつむいたまま作業している間もIDを保つ。滞在が終われば捨てる。
9. 同じフレームに写っている2つのトラックは別人（cannot-link）。

**判定と覚え直し**（A が較正して数字を決める）
- 各IDに「核テンプレート（登録時・固定）」と「来訪ごとのテンプレート（上限10〜20本）」。姿勢帯ごとに「正面の重心」「傾きの重心」を持つ。
- 3値：確定（例：正面 ≥0.45、傾き ≥0.55）／保留（IDを付けず、覚えも更新しない）／新規（全IDに対して <0.25、良い正面が5枚以上・3秒以上）。数字は r50 での出発点で、**必ず自分のデータで較正**。
- 覚えに足すのはトラック単位、確定しきい値よりさらに高いときだけ（例：≥0.60）。核との類似度が低いもの（例：<0.40）は足さない。上限に達したら重心から一番遠い1本を捨てる。
- 毎晩、全テンプレートを制約付きでクラスタリングし、割れたIDを統合（仮ID→正規IDの対応表をログに残す）。
- 「30秒以上いた人だけ登録」はやめてよい。

**1台構成ならではの工夫**
- **最初の一言を全員に同じ中立な言葉にして、顔を上げさせる**（スピーカーをカメラの真下か真横に）。その後、人ごとの態度に切り替える。
- Tapo の設定：夜間の自動の長時間露光をオフにし、動きのブレを減らす。

**記録**（再生を本番と同じ入力にするため）
検出1件ごとに：時刻・フレームID・トラックID・枠・5点・pitch/yaw・顔幅・ボケ・埋め込み（float16）・整列済み112×112の切り抜き（JPEG）。

## 追記：マック側の実測の要点（2026-09-22・マックのトーク。詳細はマックの `tracker/引き継ぎ_マック側の実測_2026-09-22.md`）

9/22 本人決定：カメラを受ける先は今の構成のまま。追跡構成は今回は見送り。次に検討するときの土台として残す。

1. **計算力は足りる。足りないのは通信。**M1 で1コマ 52ms（19fps 相当）、顔は CoreML で CPU の7倍。実際に処理できた別々の瞬間は 5.0〜5.5fps（良いとき）〜2.9fps（悪いとき）
2. **副ストリーム（1280×720）では顔が小さすぎる。**実測の顔幅は遠くの人 12〜16px、カメラのすぐ前で 63px（横顔）。本番の下限 70px に届かない。主ストリームなら 22〜23px／113px 相当になる見込み（横幅1.8倍からの推測・実測ではない）
3. **「1滞在＝1トラック」は未検証。**計65分の記録で人の入室を1度も捉えられなかった（無人の時間帯）。次に検討するときは、ここを最初に確かめる
4. **通信の作法**：有線 LAN を挿すと Wi-Fi が眠って 0.1fps に落ちる／RTSP は UDP＋低遅延（4.2→8.0/秒）／主ストリームは他が受けている間は 0.1fps で使えない／Wi-Fi は黙って別ネットへ移るので **ping ではなく映像が1コマ来ることで確かめる**／SSID はコードから読めない
5. **24時間運転向けに2つの不具合を直して確認済み**：固まる問題（別スレッドから映像を切らない＋読み取りに5秒の時間切れ）と、弱った回線を叩き続ける問題（待ち時間 2→8→30秒・作り直し間隔 10→最大60秒）。ただし「切れてから実際に映像が戻る」場面はまだ踏めていない

記録（マックの `tracker/rec/` の3本）はそのまま残してある。
