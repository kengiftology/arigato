# 夜、誰も居ないのに送り続けていないか（2026-09-30 実測）

## 疑っていたこと（流れの確認トークからの申し送り）

> 雑音で「動いた」→ 大きい写真を1.5秒おきに送る → クラウドの `last_motion` が更新され続け
> 3分静かにならない → 見回りが出ない → 静かさが測り直されない → **抜け出せない**

見張りの係は、静かさ（動いたと判断する線）を **「起動・つなぎ直し・見回りで定位置に戻った時」にしか測り直さない**。
見回りは**人が来た後にしか出ない**ので、夜は静かさが古いまま残る。そこが出発点。

## 測り方

橋渡しのログ（`~/.arigato/bridge_pc/bridge.log`）には**日付が無い**ので、
**時刻が戻ったら翌日**と数えて最後の1日を取り出し、クラウドの `presence` と突き合わせた。
「速い送信」＝`計測 前の送信から=` が **5秒未満**のもの（静かなときは5分おき）。

## 結果（2026-09-30 の 0〜6時・クラウドの記録では **6時間ずっと無人**）

| | |
|---|---|
| 送信の数 | **153件**（無人なら5分おき＝72件のはず。**約2倍**） |
| 速い送信が続いた区間 | **6回** |
| いちばん長い区間 | **236秒（3分56秒）** |
| 詰まっていれば | 1.5秒おきが何十分も続き、6時間で **1万件超** |

**結論：その筋書きは起きていない。**
ただし**雑音で「動いた」は夜に6回起きていて、そのたびに最大4分、無人のまま速く送っている。**
毎回ひとりでに抜け出している。**一歩手前ではある。**

## いまは直さない（2026-09-30・B の判断）

- **起きていない不具合に、試していない動きを足すほうが危ない。**観察期の開始は 10/5
- **測り方ができたので、再発すればすぐ分かる**（下の見方）
- 入れるなら**観察期の数日の実測を見てから**。そのほうが線の置き方にも根拠がつく

## 再発の見方（週1の点検に足す）

無人の時間帯（夜 0〜6時）の送信数を数える。

| 送信数 | 読み方 |
|---|---|
| 約 **72件** | ふつう（5分おき） |
| **150件前後** | 雑音で数回起きている（2026-09-30 はここ） |
| **数千〜1万件** | **詰まっている。**手当て（下）を入れる |

**手当ての案（本人と流れの確認トークで合意済み・入れるのは確かめてから）**
- **A**：C3 の人感が無人でしばらく（例：30分）たったら、1回測り直す
- **B**：C3 の人感が無人なのに「動いた」が続いたら（例：5分）、測り直す
- どちらも**人が居ない時に限る**ので、撮り逃しは増えない。測り直しの合図（`w.reset`）を立てる条件を足すだけ

## ついでに分かったこと

- **1周のうち 50〜70秒は写真を送らない。**「使える1枚か」を測る約14.5秒 × 1周5回で、
  1周（実測 126〜147秒）の**およそ半分**にあたる。**その間に人が入ると撮り逃す**
- 「動きあり」のログは**動き始めの1回だけ**。回数の材料にはならない（連続しているかは送信の間隔で見る）
