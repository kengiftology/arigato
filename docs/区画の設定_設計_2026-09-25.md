# 区画の設定：コードから外に出す（2026-09-25）

## なぜ

いま、区画ごとの知識が**コードに直接書いてある**。

| いまの置き場 | 中身 |
|---|---|
| `ZONE_NAMES` | 区画の名前（シンクだけ） |
| `ZONE_FIXTURES` | 「備え付けなので見ない物」の説明文 |
| `_SINK_EMPTY_Q` | 「空か」を聞く問い（シンク専用の文面） |
| `SINK_ROTATE` / `SINK_HIDE` | 切り出し方（回転・塗りつぶす範囲） |
| `AIM_REF_OBJ` | 見本の写真（**1枚しか無い**） |
| `VIEW_BAND` | 向きを見分けるのに使う範囲（**全区画で同じ**） |
| `AIM_MIN_CONF` | 同じ向きと認める線（**全区画で同じ**） |
| `aim_fix.json` | 向きの補正（**手で決めた1組**） |

**区画を3つに増やすと、このうち下4つがそのままでは成り立たない。**
9/24 に実測したとおり、区画ごとに向きも帯も線も違う。
**測らずに使い回すと、静かに全部飛ばされる**（気づけない形で止まる）。

## 置き場

`spirit/state` の中に、区画の配列として持つ。

```json
{
  "id": "rack",
  "name": "水切り",
  "active": true,
  "app_zone": "",
  "pose": "-1.00_-1.00",
  "aim": { "ref": "spirit/zoneref/rack.jpg", "band": [0.0, 1.0],
           "min_conf": 0.30, "fix": [0.0, 0.0] },
  "crop": { "rotate": 180, "hide_from": null },
  "ask": {
    "scene": "写真は共有キッチンの水切りかごを天井近くから見下ろしたものです。",
    "fixtures": "かごそのもの（ステンレスの枠と受け皿）は備え付けです。物ではありません。",
    "question": "かごの中に、洗い終わった食器がいっぱいに入っていますか？",
    "bad_is": true
  },
  "rule": { "kind": "dwell", "seconds": 7200 },
  "decided": "2026-09-25 本人。向きは9/24の一覧から本人が指名。線は9/24の実測（同じ向き1.005／違う向き最大0.050）から0.30"
}
```

**`decided` は必須にする。**`aim_fix.json` の `+0.12` が 9/22 に手で決めた値のまま古くなり、
9/23〜24 に 20時間50分の停止を招いた。**手で決めた数字は古くなる。**
区画が3つになれば手で決めた数字は3倍になるので、**いつ・どうやって決めたかを数字と一緒に置く。**

## 判定の決まり（`rule`）

### `change`（いまのシンクのやり方）

前と今を見比べて、**変わった向き**だけを見る。絶対の状態は見ない。

- 悪い→よい ＝ 片づいた（機嫌が1段よくなる）
- よい→悪い ＝ 散らかった（1段悪くなる）
- 同じ→同じ ＝ 何もしない（光が変わっても動かない）

### `dwell`（新しい。水切り用・2026-09-25 本人の指示）

> 「水切りが続けてパンパンの時は散らかってる判定でよい。
> 　2時間経過してもパンパンの時は綺麗にしてほしい。」

**同じ悪い状態が続いていること自体を、悪い状態として扱う。**

- 悪い状態になった時刻（`state_since`）を区画ごとに覚える
- **`seconds` を超えて悪いままなら、その区画は「散らかっている」**
- よい状態に戻ったら `state_since` を消す

**`change` との違い**：`change` は「誰かが何かした瞬間」しか動かない。
`dwell` は**誰も来なくても時間が経てば動く**。見回りは誰も居なくても30分に1回出るので、そこで数える。

### なぜ「催促」にしないか

「2時間たったら綺麗にしてほしい」を、**言葉で促す形にはしない**。
設計原則#15（反応はイベントではなく状態にする）・#19（即レスは叱責に見える）に反する。
**表情が「散らかっている」になる**、それだけ。
気づいた人が片づければ、次の見回りで機嫌が戻る。**そこに気づくかどうかは人に委ねる。**

## 入れる順番

1. **設定の読み込みだけ先に入れる。**いまの定数を既定値にして、**動きが1つも変わらないことを実証する**
   - 同じ写真を、入れ替え前後の両方の判定にかけて、結果が一致することを見せる
2. そのあと `rack` を足す（見本は 9/26 午前に本人が確認）
3. `table` は 9/27、`ih` は 9/30

**1 を飛ばさない。**動きが変わっていないことを見せずに入れると、
次に何か壊れたとき「設定化のせいか、区画を増やしたせいか」が分からなくなる。
