## 1. 結論（次に検討する人が最初に読む3行）

1. **計算力は足りる。足りないのは通信。** M1 で 追跡39ms＋顔11〜18ms＝1コマ約52ms（19fps相当）。
   一方、Wi-Fi 経由で実際に処理できた「別々の瞬間」は 5.0〜5.5fps（良いとき）〜2.9fps（悪いとき）。
2. **副ストリーム(1280x720)では顔が小さすぎる。** 実測した顔幅は、遠くの人 12〜16px、
   カメラのすぐ前に立った人で 63px（横顔）。本番の下限は 70px。
3. **「1滞在＝1トラック」は未検証。** 計65分の記録で人の入室を1度も捉えられなかった
   （9/18夜・9/19昼とも、キッチンがほぼ無人の時間帯だった）。ここが B の成否を決める。

## 2. 環境（そのまま再現できる）

- Python は uv で入れた 3.11（`~/.local/bin/uv`）。`cd tracker && uv sync` で `.venv` ができる
- 構成：ultralytics(YOLO11n)＋ByteTrack、insightface(SCRFD＋buffalo_l＋landmark_3d_68)
- **顔の処理は CoreML で動かす**（実行方式を替えるだけで CPU の7倍速い）
- `/usr/local` にある Intel 用の道具は使えない（uv の導入もこれで一度失敗した）
- カメラの鍵は `~/.arigato/tapo.env`（本人が書く。コードにもチャットにも書かない）

## 3. 速さの実測

| 構成 | 追跡 | 顔（2人分） | 合計 |
|---|---|---|---|
| YOLO11n CPU ＋ 顔 CPU | 36ms | 249ms | 285ms |
| **YOLO11n CPU ＋ 顔 CoreML** | 33ms | 35ms | **68ms** |
| YOLO11n MPS ＋ 顔 CoreML | 34ms | 42ms | 76ms |
| YOLO11n ONNX ＋ 顔 CoreML | 40ms | 34ms | 74ms |

- 2304x1296 でも 69ms/コマ（人の枠の中だけで顔を探すため、画面が大きくても変わらない）
- 顔は1人あたり約17ms。5人同時・毎コマなら約120ms。**顔は毎コマでなく間引く設計にする**
- プロセスのメモリ約1.2GB。マック全体で7GB使用中だったので、24時間運転では他を閉じる前提

## 4. 通信（ここが本当の壁。次回も最初にここを確かめること）

- **有線LANを挿すと macOS が Wi-Fi を眠らせる。**映像が 0.1fps まで落ちた。挿さないこと
- **RTSP は UDP＋低遅延で受ける。**TCP は再送待ちで固まり、同じ20秒で「別々の瞬間」が
  4.2/秒だったものが、UDP では 8.0/秒になった
- **主ストリームは、ラズパイ/PC が受けている間は使えない**（15秒で2コマ＝0.1fps）
- **Wi-Fi が黙って別のネットワークへ移る。**9/19 にマック（12:50）も PC（16:42）も実際に移った。
  `ping` が通ることは接続できる証拠にならない（**映像が1コマ来ることで確かめる**）
- **SSID はコードから読めない**（位置情報の許可が無いと `<redacted>`）。IP と「映像が来るか」で代用する

## 5. 24時間動かすために直した2つの不具合（どちらも実際に踏んだ）

1. **固まる**（9/19 14:07、75分ぶんを取り逃した）
   - 原因：読んでいる最中の映像を別の流れから `cap.release()` で切っていた／読み取りに時間切れが無かった
   - 直し：RTSP に `timeout;5000000`（5秒）を付ける。切るのではなく**読み手ごと作り直す**
   - 確認：黙ったままのサーバ相手に 5.2秒であきらめる。作り直しは 0.00秒
2. **弱った回線を叩き続ける**（9/19 20:45〜21:07、22分で99回）
   - 直し：作り直しても待ち時間を引き継いで倍にする（2→8→30秒）。記録側の間隔も10→最大60秒
